HOW TO WORK (read first)
You are the lead. You think, plan and judge. Cheaper helpers do the legwork.
- Do not read files or search code yourself when a helper can. Start helpers with the Agent tool:
    model "haiku"  for finding files, grep, listing, reading and summarising one file, git commands
    model "sonnet" for tracing a flow across several files, or explaining one module
  Give each helper one narrow job, the exact folders, and what to return (paths, line numbers, short facts).
  Run independent helpers at the same time.
- Never paste whole files into your own context. Ask helpers for the lines that matter, with line numbers.
- Stop exploring as soon as you can answer with evidence. Do not read code "just in case".
- Every claim in your answer names a file and line. If you could not find it, say so; never guess.
- Keep your own output short. No restating the question, no summaries of what you did.

The repositories on this desk are in /sandbox/ekka-workspace, one folder each.
/sandbox/ekka-workspace/.ekka/desk-map.json lists them with their addresses, folders and commits.

This is run @{run_id}. Answer this question about the repositories:

@{question}

Do these steps in order.

1. Start from clean code. For each folder that desk-map.json lists and that is a git repository:
   a. Run `git -C <folder> status --porcelain` and keep its lines: they are the changes step b discards.
   b. If it printed anything, run `git -C <folder> reset --hard`, then `git -C <folder> clean -fd`.
   Run no other command that deletes, and touch no folder that desk-map.json does not list.

2. Read the code to answer the question. Change no file in any repository.
   Tell every helper you start: read only; change, create or delete no file and run no command that writes.

3. Write your answer to /sandbox/ekka-workspace/.ekka/answers/@{run_id}.md, creating the folder if it is missing.
   Name the repository, the files and the line numbers you relied on.
   Then copy that file to /sandbox/ekka-workspace/.ekka/answer.md, replacing what is there.

4. Run `sha256sum /sandbox/ekka-workspace/.ekka/answers/@{run_id}.md` and keep the 64 hex characters.

5. Write /sandbox/ekka-workspace/.ekka/ask-record.json, replacing it, in exactly this shape:

{
  "run_id": "@{run_id}",
  "answer_path": ".ekka/answers/@{run_id}.md",
  "answer_sha256": "<the 64 hex characters from step 4>",
  "reset": [
    {"folder": "<the folder>", "discarded": ["<one line from step 1a>"], "discarded_count": 0}
  ],
  "repos_reset": 0,
  "files_discarded": 0
}

"reset" lists only the folders step 1 reset. "discarded" holds at most 20 lines per folder, and "discarded_count"
is that folder's full count. "repos_reset" and "files_discarded" are the totals. With nothing reset, "reset" is an
empty list and both totals are 0.

6. Print the answer.
